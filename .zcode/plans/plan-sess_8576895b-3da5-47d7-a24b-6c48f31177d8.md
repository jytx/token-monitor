# 多账号能力通用化：DeepSeek / Z.ai(GLM) 接入 + minimaxAccounts 泛化

## 目标

把「单 API key 型供应商多账号」从 MiniMax 专用泛化为通用能力，本次接入 **DeepSeek** 和 **Z.ai(GLM)**（用户点名）。OAuth/cookie/多字段凭据（kimi、zaiteam、volcengine、qoder 等）不在本次范围。

## 关键设计决策

- **`minimaxAccounts.js` 泛化为 `src/shared/apiKeyAccounts.js`**：全部函数带 `provider` 参数（`managedAccountKey(provider, key)`、`normalizeApiKeyManagedAccounts(provider, value)`、`scopedApiKeyManagedAccounts(provider, value, scope)`、`createApiKeyManagedAccount(provider, keyValue, label, existing)`、`apiKeyAccountDisplayLabel`）。删除 `minimaxAccounts.js`，minimaxLimits/main/tests 全部改引通用层（分支未推远端，可自由重构）。三处重复的 `cleanSecret`（limitCollector/zaiLimits/minimaxAccounts）合并到通用层。
- **main 侧装配工厂 `src/electron/apiKeyAccountControllers.js`**：`createApiKeyAccountProvider(provider, { validateAccount })` 返回 `{ accountsForRenderer, managedAccountsForCollector, addAccount, updateAccount, migrateLegacyKey, lifecycle }`——add/update/迁移的骨架三家同构（活体验证 → 写凭据 → 存元数据 → 账号级失效，换 key = 换身份双失效），差异只在验证函数与错误码。MiniMax 现有的 ~200 行专用块迁移到工厂，三家各 ~20 行装配。
- **Z.ai 的 region 保持全局共享**（`settings.zaiApiRegion`，region select 留在卡片内、组级生效，所有账号打同一 region 端点）。per-account region 留作后续扩展（需要 accountKey 掺 region 防同 key 双 region 撞去重，本次不做）。
- **DeepSeek 的 fetch 从 limitCollector.js 抽到 `src/shared/deepseekLimits.js`** 独立文件（多账号入口 + 单账号 probe + 带身份的失败行），limitCollector re-export `deepseekToken`/`fetchDeepSeekLimits` 保持现有引用兼容。`deepseekBalanceHistory` 已按 accountKey 分键，无需改。
- **兼容路径与迁移**：与 minimax 相同——无账号时走旧单 key/env 路径（headless agent 不受影响）；启动时 `migrateLegacyDeepSeekApiKey`/`migrateLegacyZaiApiKey`（幂等，accountKey 公式 `hashKey(provider, key)` 与现状一致，身份与订阅绑定连续）。
- **UI**：deepseek/zai 卡片改成 MiniMax 同款多账号 DOM（账号列表 + 添加手风琴 + 标签输入）；renderer 抽 `setupManagedAccountCard(prefix, ...)` 共用绑定（三家共用，含「复用添加表单做编辑」逻辑）。DeepSeek 的六个单账号专属函数（renderDeepseekStatus/pending 机制等）删除；zai 从 externalLimitAccountConfig 泛化表中移除。旧 Logout/Refresh 按钮随多账号化移除（每行启停/删除，编辑走表单）。

## 改动清单

### 一、shared 层

1. **新增 `src/shared/apiKeyAccounts.js`**（由 minimaxAccounts.js 泛化，~140 行）；删除 minimaxAccounts.js，更新全部引用（minimaxLimits.js、main.js、tests）。
2. **新增 `src/shared/deepseekLimits.js`**：`deepseekToken`（env 回退 DEEPSEEK_API_KEY/DEEPSEEK_KEY）、`probeDeepSeekAccountKey(key, account, deps)`（现有探测逻辑，成功行 accountLabel 改「标签 || 尾号」，'Pay-as-you-go' 留 planLabel 语义位）、`deepseekStatusProvider(status, updatedAt, account)`（失败行带账号身份）、`fetchDeepSeekLimits(options, deps)`（多账号入口 + 单 key 兼容路径）。limitCollector.js 删除内联实现、re-export 兼容。
3. **`src/shared/zaiLimits.js`**：`fetchZaiLimits` 改多账号入口（scoped 过滤 + Promise.all 逐账号 + 失败行带身份），无账号时保留单 key/env 路径；region 从全局 options 读取不变。
4. **`src/shared/limits.js`**：`providerCollapseKey` 白名单加 `deepseek`、`zai`。
5. **`src/shared/limitCollector.js`**：`providerPhysicalBoundMs` 加 deepseek/zai 按账号数放大分支。

### 二、electron 层

6. **新增 `src/electron/apiKeyAccountControllers.js`**（~220 行）：装配工厂 + `migrateLegacyApiKeyAccounts(provider, ...)` 通用迁移。
7. **`main.js`**：DEFAULT_SETTINGS 加 `deepseekManagedAccounts/zaiManagedAccounts: []`；三家（minimax/deepseek/zai）切换到工厂（删除 minimax 专用块）；`settingsForRenderer` 派生两家 managedAccounts 与 configured；`electronLimitsConfig` 注入；`ensureSettingsLoaded` 调两家迁移；settings:update 拒绝两个新 key 的 patch。
8. **`runtimeConfig.js`**：`LIMIT_PROVIDER_SETTING_KEYS` 的 deepseek/zai 条目加 managedAccounts key；`limitsConfigFromSettings` 透传两个新数组。
9. **`preload.js`**：`deepseek:`/`zai:` namespace（accounts/addAccount/updateAccount/removeAccount/setAccountEnabled + onAccounts push）。

### 三、renderer 层

10. **`index.html`**：deepseek/zai 卡片改多账号 DOM（AccountList/AccountEmpty/AddToggle/AddDetails/key+label 输入）；zai 保留 region select（组级共享）。
11. **`app.js`**：删 deepseek 专属六函数与 external 表的 zai 条目；两家 `renderXxxStatus` 走 `renderManagedAccountList`（含 beginEdit 复用添加表单）；抽 `setupManagedAccountCard` 共用绑定（minimax 一并切换）；limits 页 `renderLimits` 加两家组渲染分支；`LIMIT_ACCOUNT_TITLES` 加 deepseek/zai（accountLabel 回退，'Pay-as-you-go'/'GLM Coding' 套餐名不作账号名）。
12. **i18n**：deepseek/zai 补齐多账号文案（nAccounts/connected/toggle/remove/edit/editingHint/duplicateAccount/invalidApiKey 等）×5 locale；删除两家的死 key（saveApiKey/statusSet 等随 UI 改版失效的）。

## 风险与边界

- 旧 hub 对 deepseek/zai 多行的折叠行为与 minimax 相同（需同步更新 hub），API.md 已有统一说明。
- zai region 共享意味着两个账号必须同 region 使用；用户如有跨 region 双账号需求，后续做 per-account region。
- cursorSettingsLayout.test.js 有顺序敏感的多行正则（deepseek/minimax/zai 卡片连排），是本次最大的测试维护点。
- zaiteam（独立 provider、仅 CN）与 kimi（双凭据）明确不动。
